## What Went Well

- EventStore mirroring reduced architectural drift and gave developers concrete patterns for project layout, package metadata, ServiceDefaults, Aspire topology, and CI structure.
- Story records became useful implementation artifacts, not just tracking shells. They preserved review outcomes, fixes, deviations, and verification evidence.
- The team caught and fixed review gaps in Story 1.1 and Story 1.3, including test discovery, coverage collection, Tier 3 result artifacts, and release suite coverage.
- Story 1.2 handled architecture drift responsibly. The team documented why DAPR components moved to `src/Hexalith.Tenants.AppHost/DaprComponents/` and why `actors.yaml` was not created.
- CI/CD uses pinned action SHAs and minimal CI permissions, which improves supply-chain posture from the first epic.

## Challenges

Bob (Scrum Master): "No blame here. The pattern is clear: the project moved fast by following EventStore, but the dependency on EventStore also became the main source of current readiness risk."

- Current `dotnet test Hexalith.Tenants.slnx --configuration Release` fails during restore because EventStore submodule projects treat NuGet vulnerability warnings as errors for `OpenTelemetry.Api` 1.15.1 and `OpenTelemetry.Exporter.OpenTelemetryProtocol` 1.15.1.
- Story 1.3's markdown record still contains stale tag-release language in several places, while the actual `.github/workflows/release.yml` runs semantic-release on `main`.
- `.releaserc.json` builds, packs, pushes NuGet packages, creates GitHub release assets, and updates CHANGELOG.md, but the visible release path does not show an explicit expected-package-count validation gate.
- The CI story text says DAPR initialization is required for Tier 2 and release validation, but the current CI workflow does not install or initialize DAPR before running Server.Tests.
- The project now has a local AGENTS.md rule to avoid recursive nested submodule initialization unless explicitly requested. Story records and workflows use recursive submodule language because of the EventStore ProjectReference dependency. This should be reconciled intentionally.

## Lessons Learned

1. Reference implementations are powerful, but they create inherited risk. EventStore alignment should include dependency health checks, not only structure and naming checks.
2. Story artifacts need a final sync pass after code review. Story 1.3's implementation evolved toward semantic-release, but some narrative sections still describe an older tag-release model.
3. CI requirements need to be validated against actual workflow files. It is easy for acceptance criteria, story notes, and workflow behavior to diverge.
4. Architecture deviations are healthy when explicit. Story 1.2 is the model: record the deviation, name the source of truth, and explain why.
5. Foundation epics should finish with a reproducible verification command that still works after upstream dependency changes.
