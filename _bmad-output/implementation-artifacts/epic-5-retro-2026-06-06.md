## What Went Well

- The approved `FC-AUD` flat DataGrid fallback became real UI without claiming a reusable `<AuditTimeline>` exists.
- The fixed backend surface held across the epic. Audit, receipts, recovery, correction preview, proof lookup, and command status all reuse existing query/command gateways.
- Support safety improved story by story. Audit rows, receipts, correction panels, proof links, and copy actions all avoid raw payloads, tokens, protected cursors, ETags, correlation ids, stack traces, and PII.
- The non-collapse invariant stayed intact. Accepted command, projection confirmation, audit availability, audit delayed/unavailable, missing support, degraded, and unable-to-verify remain separate states.
- Story 5.6 closed the highest Story 5.5 review gap by wiring tenant-domain role/current-state evidence into live correction preview and submission.
- Focused UI validation scaled from 503 passing tests in Story 5.1 to 610 passing UI tests in Story 5.6 through the xUnit v3 executable fallback.

## Challenges

- Story 5.5 shipped with a deliberate fail-closed live correction path because role/current-state evidence was not wired yet. Story 5.6 resolved the tenant-domain side, but this is a useful reminder to separate model-complete from live-flow-complete.
- Global-administrator correction remains fail-closed because Epic 4 command stories 4.3 and 4.4 are still backlog. Epic 5 correctly avoided inventing partial global-admin command support.
- Several review fixes centered on localized copy and machine-token leakage: source-kind labels, correction conflict messages, and snapshot labels all needed explicit resource-backed wording.
- Focus behavior improved in Story 5.6 with launcher refocus, but terminal in-panel focus movement remains a residual accessibility polish item.
- Correction status refresh currently performs redundant projection re-query work in one path. It is functionally correct, but should be tightened before broader reuse.
- Server and integration validation remained blocked by pre-existing AppHost/DAPR documentation and local environment failures; Epic 5 completion relies on focused UI, Tier 1 executable, and solution build evidence.

## Key Learnings

- Audit and recovery can stay entirely UI/BFF-composed when the audit read model is rich enough. A new backend receipt or proof-link endpoint was not needed.
- Forward recovery needs current projection truth, not only historical audit proof. The Story 5.5 to 5.6 handoff made this concrete.
- Copy safety needs layered enforcement: row allow-lists, receipt builders, support-safe classifiers, resource-backed UI text, and static tests all caught different classes of leaks.
- Global-administrator governance is not a tenant-membership variant. Keeping its correction path blocked was the right boundary until Epic 4 command support exists.
- Review findings should be folded into the next story immediately. Story 5.6 directly consumed the Story 5.5 high and low follow-ups instead of leaving them as ambient debt.
