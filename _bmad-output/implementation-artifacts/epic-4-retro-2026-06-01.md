## What Went Well

- Story 4.1 corrected the event publication contract without collapsing aggregate domains. Tenant and global-administrator events now publish to the shared `tenants.events` topic while preserving `global-administrators` as its own command/projection domain.
- Story 4.2 kept the Client package adoption surface small. `AddHexalithTenants()` remains the primary registration path, defaults are `Tenants`, `pubsub`, and `tenants.events`, and the stale `CommandApiAppId = "commandapi"` option was removed instead of preserved.
- Story 4.3 made selected event handling concise through `AddTenantEventHandler<TEvent, THandler>()`. Custom handlers can share one implementation across multiple event types and are resolved through an event scope.
- Story 4.4 hardened the local projection path with fail-closed access behavior, case-sensitive identifiers, clone-on-read/write storage, duplicate-delivery tests, and sample endpoint coverage.
- Story 4.5 completed reaction behavior for membership, lifecycle, and configuration events. The Client now records bounded `LastEvent` metadata and rejects payload/envelope tenant mismatches before dispatch.
- Story 4.6 turned the implementation into copyable adoption guidance. The docs now explain `MessageId` deduplication, aggregate-local `SequenceNumber` limits, local projection behavior, production dedup/store choices, and sample setup using only public packages.
- The team consistently used direct xUnit fallback evidence after VSTest could build but could not open its sandbox-denied listener. Story records distinguish environmental runner failure from application test failure.

## Challenges

- Epic 4 restarted with active story files that superseded older artifacts. The workflow had to ignore stale files such as the previous client-registration and combined sample/idempotency stories.
- EventStore ownership boundaries created real implementation friction. Story 4.1 required a narrow EventStore publisher topic override while keeping Tenants domain code free of broker-specific coupling.
- Stale topology language kept reappearing in docs and defaults. `commandapi` had been removed from AppHost/resource configuration, but old docs still referred to it as the local service name.
- Sample logging needed review hardening. Earlier wording and code risked exposing payload user IDs, role names, or configuration values; the final handler logs bounded metadata only.
- The default Client projection and dedup stores are intentionally in-memory. That is correct for local and single-instance samples, but production consumers must opt into durable/shared stores when they need cross-instance coordination.
- Full live DAPR pub/sub confidence remains environment-dependent. Local DAPR Redis, placement, scheduler, and sidecar prerequisites are outside Tier 1 evidence and are gated in integration tests.

## Key Learnings

1. Event topic shape is a contract. Shared topic behavior for `tenants.events` must be configured where publication actually occurs: the EventStore command gateway, not only the Tenants host.
2. Consumer ergonomics depend on defaults being current. A public option with a stale app id is worse than no option when no runtime service consumes it.
3. Idempotency is layered. `TenantEventProcessor` deduplicates by `MessageId`, while projection handlers still need naturally idempotent set/remove/assign operations.
4. Envelope and payload tenant identity must agree before dispatch. Rejecting mismatches prevents malformed broker messages from updating the wrong local projection.
5. Local consumer projections and server-owned query projections are different architectures. Epic 5 must not reuse Client in-memory assumptions for centralized query read models.
6. Documentation changes should be verified against code, not copied from story notes. The audit below updated only confirmed mismatches.

## Next Epic Preview

Epic 5: Operators and Developers Can Query Tenant State and Audit Access

Epic 5 depends on Epic 4 outcomes but changes ownership:

- Epic 4 local projections live in consuming services and support runtime tenant-aware behavior.
- Epic 5 server projections live in the Tenants service and support administrative discovery, detail views, membership lookup, audit queries, and cursor-paginated APIs.
- Epic 5 must use durable projection write policies, query-side authorization, cursor security, and conflict diagnostics. It must not treat the Client package's in-memory store as a server projection persistence model.

Epic update required: No.

## Preparation For Epic 5

Critical preparation:

- Use Epic 4 event metadata (`MessageId`, `SequenceNumber`, tenant/domain/aggregate identity) as input to server projection diagnostics, not as a replacement for durable projection write safety.
- Decide and verify server projection persistence behavior before relying on tenant list, detail, users, memberships, or audit endpoints.
- Keep query authorization inside projection/query handling instead of only in REST controllers.
- Ensure cursor tokens remain opaque, signed, and scope-bound before endpoint stories claim completion.

Parallel preparation:

- Reuse Epic 4 docs terminology for at-least-once delivery, eventual consistency, and aggregate-local sequence limits.
- Link consumer-local projection guidance from adoption docs without implying it is the Tenants query model.
- Keep DAPR live verification gated and explicit when local prerequisites are unavailable.

## Significant Discovery Check

Epic update required: No.

Significant implementation learnings handled inside Epic 4:

- Global-administrator events need an EventStore publisher topic override so they publish on `tenants.events` without changing their aggregate domain.
- `commandapi` is not the current AppHost resource/app id. The local command gateway resource is `eventstore`.
- Default sample projection storage is in-memory through `InMemoryTenantProjectionStore`, not Redis/DAPR state store.
- Sample logs are support-safe metadata logs, not payload-value logs.
- The default AppHost starts Keycloak unless `EnableKeycloak=false`; local token instructions must not assume the symmetric-key fallback is the default path.
- `SequenceNumber` is aggregate-local metadata and must not be documented as global ordering.

These discoveries require documentation corrections and continued Epic 5 guardrails, but they do not require replanning Epic 5.
