## Challenges

Charlie (Senior Dev): "Epic 10 also exposed how much friction the surrounding environment costs us when stories are technically correct but cannot be validated end-to-end."

- Story 10.3A was structurally the longest story in the epic because its real cost was making EventStore solution validation possible in this workspace, not the actor-boundary cancellation work. The initial implementation succeeded on the API surface but full validation was repeatedly blocked by: (a) the absent nested `Hexalith.EventStore/Hexalith.Tenants/...` project references in `Hexalith.EventStore.slnx`, (b) a `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.8 vs 10.0.5 mismatch in `Server.Tests`, (c) `AspireTopologyTests` `TaskCanceledException` in the fixture health check. Fixes required generalizing `HexalithTenantsBasePath`, removing the static `/tenants/` block from the solution, adding a conditional Server.Tests project-reference fallback, and eventually publishing `bcccd504` upstream. That is four cross-cutting infra changes piggybacking on one prerequisite story.
- DAPR actor cancellation transport was the highest-risk design decision and almost slipped. Story 10.3A's first instinct was to add `CancellationToken` to `IProjectionActor.QueryAsync(envelope, ct)`. Verification against DAPR actor proxy/runtime semantics ruled that out — the token would have been serialized as a normal argument, not wired to transport cancellation. The chosen path (`ActorProxy.InvokeMethodAsync<QueryEnvelope, QueryResult>(nameof(QueryAsync), envelope, cancellationToken)` via the weak proxy base) is correct but has a documented fallback boundary for non-`ActorProxy` substitutes — code-review D1 had to settle that this fallback is acceptable evidence, not a defect.
- Cancellation message preservation through `async`/`await` is unsolvable as written. The .NET async state machine transitions an `OperationCanceledException` thrown inside an async method to `TaskStatus.Canceled`, and the `await` re-throws a fresh `System.Threading.Tasks.TaskCanceledException` with the default `"A task was canceled."` message. Neither NSubstitute nor the DAPR actor SDK is responsible. The cleanup was right (replace message assertions with type-identity assertions plus structured-log non-emission assertions), but it took the review's D3 root-cause investigation to recognize it was not a behavioral bug.
- Submodule pointer advances during code review remain a checkpoint, not a routine. Story 10.3B's review observed that the EventStore submodule pointer had moved from `bcccd504` to `8d740e5a` (the 1-commit descendant adding "fix(server): use weak ActorProxy in QueryRouter to fix list-tenants NRE"). The descendant was required to make `list-tenants` query routing actually work, but the review had to flag it as a Decision and Jerome had to sanction the bump explicitly. The story-spec covered this in Task L67 and Dev Notes L87, so the process worked, but the muscle memory is "always pause for an explicit human decision."
- Story 10.4 carried 10.3B-attributed work and the review accepted it retroactively. Commit `c8246f6` added `CancellationToken cancellationToken = default` to `TenantProjectionHandler.ProjectAsync` and 7 `ThrowIfCancellationRequested` calls inside `TenantProjectionWritePolicy.SaveWithOptimisticConcurrencyAsync` / `SaveMergedWithOptimisticConcurrencyAsync`; commit `3e27ab6` added three cancellation tests in `TenantProjectionHandlerTests.cs`. Spec lines 76-77 of 10.4 explicitly reserved cancellation behavior for Story 10.3B. The review's D1 decision was to accept retroactively and record the procedural attribution in `deferred-work.md`. That is the lighter version of the Epic 9 Story 9.5 piggyback pattern — better outcome (in-spec adjacent surface, not a submodule SDK pin), same shape (scope creep into a different story's commits).
- The deferred-work list grew, not shrank. Epic 10 added entries from every story: backoff/jitter, `MaxAttempts >= 1` validation, `AggregateId` empty-string validation, `TenantAuditReadModel` blob unbounded growth, DaprClient transport exception classification (`DaprException`, `RpcException(Unavailable|DeadlineExceeded)`), empty/whitespace ETag wedge under `FirstWrite`, `applyEvent` no-cancellation-token (cancellation observed only between events), out-of-order `UserAddedToTenant` before `TenantCreated` silently dropping membership in `TenantIndexReadModel`, `NullReferenceException` defenses missing for JSON-deserialized `null` `Entries`, per-string length cap missing in `BuildBoundedMessageIds`, free-form `stateKeyCategory` parameter embedded in exception messages, empty/all-null `request.Events` triggering full retry cycles, `_loggedOrphanMemberships` HashSet still unbounded per actor lifetime, predev preflight tooling artifacts still racing on write. R9-A7 was supposed to drain this list before Epic 10 closed; Epic 10 added to it instead.
- The `predev-preflight-*.json` tooling artifacts are still committing dirty-tree snapshots with absolute Windows paths. Recent git log shows `chore(automation): record predev hardening preflight failure` commits as recently as Epic 11 work. Story 10.3A's second-pass review specifically had to restore a transient failed snapshot the review worktree had captured. R9-A5 named this exactly; nothing was done to either gitignore the artifacts or normalize the paths.
- Story 10.3B carried cancellation-checkpoint placement inconsistencies into `deferred-work.md`: missing token check between authorization and pagination in `HandleGetTenantUsersAsync`, `IsGlobalAdminAsync` checks token before but not after the DAPR read, `IsAuthorizedForTenantAsync` early-return when `Members.ContainsKey(userId)` is true does not observe the token, `GlobalAdministratorProjectionHandler` `ThrowIfCancellationRequested` inside `foreach` runs before the null-evt filter. None change observable behavior, but they are exactly the kind of "checkpoint here but not there" pattern that becomes load-bearing the first time someone touches the surrounding code.

Winston (Architect): "The retry policy works because it is bounded. It does not work because it is robust. Three immediate retries with no backoff on a hot singleton index can still exhaust under N-way contention where 10ms of jitter would have resolved everything. The deferred-work note is honest about it. Production deployment should weigh it."

## Key Lessons

1. **The one-helper-many-stories pattern paid for itself.** `TenantProjectionWritePolicy` + `ITenantProjectionStateStore` was sized for 10.1 and used unchanged by 10.2, 10.3B, and 10.4. The discipline to keep it internal (not a public Dapr abstraction) was tested by 10.3B's cancellation work and held.
2. **Acceptance criteria density during pre-dev is predictive, not bureaucratic.** Stories that landed 8–12 ACs had reviews that found patches inside their own ACs, not outside. Stories that started at five ACs found their next seven in review. The investment shifts left without changing total work.
3. **Cancellation needs a documented taxonomy boundary, not just a token.** Threading `CancellationToken` through a query path is the easy half; the hard half is refusing to map `OperationCanceledException` to `Forbidden`, `Invalid cursor`, `Tenant not found`, ETag conflict, or retry exhaustion. Tests that pin this taxonomy (10.3B's parameterized `RoleSensitiveQuery_pre_cancelled_throws_OCE_not_domain_error`) are the contract.
4. **DAPR actor transport assumptions must be verified, not inferred.** Adding `CancellationToken` to an actor interface method does not give transport cancellation; the actor proxy serializes it as a normal argument. The weak `ActorProxy.InvokeMethodAsync<TRequest, TResponse>(name, request, ct)` pattern is the supported path, with documented fallback for non-`ActorProxy` substitutes.
5. **`async`/`await` swallows cancellation messages by design.** The state machine transitions inner `OperationCanceledException` to `TaskStatus.Canceled` and the `await` re-throws a fresh `TaskCanceledException`. Substring assertions on cancellation messages are not load-bearing tests; type-identity plus structured-log non-emission assertions are.
6. **Cross-key projection writes are checkpoint-aware, not atomic.** Stories 10.1, 10.2, and 10.4 all explicitly refused to claim atomicity across tenant detail, singleton index, and audit. Replay/idempotency by `EventId` is the recovery contract; tests assert "no later writes after observed failure" and rely on replay for the rest.
7. **Conformance fixtures must drive production behavior, not parallel it.** Story 10.4's first draft made `ApplyIndexEvent` internal so the fixture could call it directly. The review reverted it and required the fixture to go through `ProjectAsync`. This is the difference between a test that observes the system and a test that reimplements the system and then agrees with itself.
8. **Cross-cutting infra changes still piggyback on stories when the spec covers them.** Epic 9 R9-A8 wanted SCP-first. Epic 10 spec-first inside story files (10.3A's `HexalithTenantsBasePath` and solution-graph changes) had a better outcome than 9.5's retroactive SCP, but it is not the same thing as a separate sprint-change proposal. The decision is whether spec-internal is good enough or whether SCP is the floor.
9. **Deferred-work entries that survive two epics are debt, not deferrals.** `_loggedOrphanMemberships` unbounded set, predev preflight tooling artifacts, cursor `IssuedAt` expiry, durable DP key persistence — all are now twice-deferred. They will not naturally migrate; they need explicit ownership and an epic that consumes them.
10. **The unfiltered regression gate flipping to green changes the operational posture.** Epic 9's retro called it "the next thing to make achievable, not aspirational." 10.3A's Aspire fixture patches achieved it (660 passed, 1 skipped). New baseline: a story is not done if the unfiltered gate is not green.

## Significant Discoveries

- **DAPR actor cancellation requires weak-proxy invocation, not interface-level token parameters.** Adding `CancellationToken` to `IProjectionActor.QueryAsync` serializes the token as a normal argument, not transport cancellation. The supported path is `ActorProxy.InvokeMethodAsync<TRequest, TResponse>(nameof(Method), request, ct)` via the weak proxy base, with a documented fallback boundary for non-`ActorProxy` substitutes used in tests. This is permanently load-bearing for any future DAPR actor cancellation work in this repo.
- **`async`/`await` does not preserve cancellation messages.** The state machine transitions inner `OperationCanceledException` to `TaskStatus.Canceled` and the `await` re-throws a fresh `TaskCanceledException` with the default message. Test patterns that rely on `exception.Message.ShouldContain(...)` for cancellation are inherently fragile and should be replaced with type-identity assertions plus structured-log non-emission assertions.
- **The EventStore solution build's `/tenants/` block was a checkout-shape assumption.** `Hexalith.EventStore.slnx` previously referenced nested `Hexalith.EventStore/Hexalith.Tenants/...` projects directly, which fails when EventStore is a root-level submodule of Tenants (the layout this repo actually uses). The fix generalizes `HexalithTenantsBasePath` for three layouts: EventStore-as-submodule-of-Tenants, EventStore-as-root-with-nested-Tenants-submodule, and EventStore-as-root-with-peer-Tenants-checkout. Tenants projects now resolve transitively, not by static solution path.
- **Pre-cancelled tokens do not preserve Tenants-local validation precedence.** `CachingProjectionActor.QueryAsync(envelope, ct)` (the EventStore base class from 10.3A) calls `ThrowIfCancellationRequested` before delegating to `ExecuteQueryAsync`. A pre-cancelled malformed-user request throws `OperationCanceledException` before the Tenants `Forbidden` short-circuit can run. The Tenants in-actor precedence still applies for cancellations that fire during actor execution. This was not obvious from the AC9 wording ("when that precedence is already externally observable") and now has its own regression-guard test.
- **Audit duplicate-`EventId` tests can pass by suppression instead of contest.** Original 10.4 patch had identical `ActorId="actor-1"` on persisted and incoming entries, so persisted-wins was indistinguishable from suppress-incoming. The review patch uses distinct `ActorId` values plus a `["source"] = "incoming"` marker to prove persisted-authoritative on payload mismatch. This is the right shape for any "persisted state wins on duplicate key" assertion.
- **`predev-preflight-latest.json` race-on-write captures intermediate worktree state.** Story 10.3A's second-pass review specifically had to restore a transient failed snapshot that the review worktree had captured before the patch sequence completed. This means R9-A5 is not only about absolute paths and committed failures; it is about the tooling overwriting a known-good snapshot with an in-flight dirty-tree state during a normal review cycle.
- **The conformance fixture and the unfiltered regression gate moved from aspirational to load-bearing in the same epic.** Story 10.4's fixture (driving production through `ProjectAsync`, per-key scripted state-store outcomes, fail-fast `MarkTerminalFailure`, captured `IReadOnlyList<KeyValuePair<string, object?>>` log state) plus 10.3A's Aspire fixture patches (660 passed / 1 skipped solution gate) together changed the meaning of "story marked done": the new baseline is that a future projection regression cannot pass conformance, and a future cross-cutting solution-build regression cannot hide behind skipped tests.
