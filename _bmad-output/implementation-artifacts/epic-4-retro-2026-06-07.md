## What Went Well

- Fixed-scope separation held across the epic. Global-administrator read, grant, and remove paths avoided tenant membership endpoints, tenant detail rows, user lookup substitutes, and tenant-domain command routing.
- Story 4.1 created an honest missing-read-support state before the read contract existed. Story 4.2 then replaced that state with a real fixed-aggregate review surface.
- Projection confirmation stayed non-negotiable. Grant succeeds only after the target appears in the fixed projection; remove succeeds only after the target is absent from that projection.
- Last-global-administrator safety was implemented as a hard unavailable/rejected path, not elevated friction or an overrideable destructive confirmation.
- Support-safety coverage remained strong: no raw claims, tokens, cursors, ETags, correlation ids, stack traces, raw payloads, or production identifiers in rendered troubleshooting copy.
- Review findings were fixed inside the story loop, including shell navigation rendering, resource parity, whitespace validation, fail-closed read support, platform-specific gateway copy, and remove-preview overflow safety.

## Challenges

- Planning artifacts and implementation direction diverged. FR19 remained marked blocked/deferred in several docs while Story 4.3 and Story 4.4 were later explicitly implemented.
- The retrospective is out of normal sequence. Epic 5 already has a retrospective, and it accurately recorded at creation that global-admin correction was blocked until Epic 4 command support existed. Epic 4 implementation has since superseded that assumption.
- Command lifecycle behavior is duplicated in local global-admin grant/remove snapshots, following existing Tenants patterns. This is acceptable for the domain module but should not become generic infrastructure here unless the shared technical modules provide it.
- Validation still depends on the xUnit v3 executable fallback when `dotnet test` hits the known .NET 10 Microsoft.Testing.Platform/VSTest path.
- Broader Server/AppHost/DAPR validation signals still contain existing environment/documentation failures outside Epic 4 UI/gateway scope.

## Key Learnings

- Governance blockers need an explicit status transition. If a story resumes after a prior blocked decision, the story file and docs should name the newer clearance or user override so future agents do not rediscover the same conflict.
- Readiness placeholders are useful when they are honest and temporary. Story 4.1 prevented false success, and Story 4.2 cleanly replaced the placeholder once the read contract existed.
- Global administrator command support must keep its own language. Tenant-command fallback copy is too easy to leak into platform-governance flows.
- SignalR remains only a freshness nudge. Both grant and remove flows correctly require projection re-query evidence for success.
- Last-admin protection is safer when blocked before submit and still handled after submit as a race-condition rejection.
