## What Went Well

- The fake command service reused production Handle methods instead of reimplementing tenant rules. That keeps tenant validation, rejections, and event production aligned with the real service.
- The API split is healthy: high-level overloads are ergonomic for normal tests, while `ProcessTenantCommand<T>(command, envelope)` gives conformance tests exact envelope control.
- Event application is explicit and defensive. Pattern matching dispatch applies known events and fails loudly when a new event is not handled.
- `EventHistory` creates a simple bridge from command tests to projection tests without introducing infrastructure.
- `InMemoryTenantProjection` reused the server read models instead of creating parallel read-model shapes.
- The conformance suite made production-test parity executable rather than aspirational. Reflection-based discovery plus an expected command count gives the suite a useful tripwire.
- Tests covered both aggregate isolation and projection isolation, which maps directly to the product promise that tenant data does not bleed between tenants.

## Challenges

Charlie (Senior Dev): "Epic 6 looked like a helper package, but it carried production semantics. A fake that is almost right would be worse than no fake because it would teach consumers the wrong behavior."

- Command envelope construction was a sharp edge. Tenant management uses `TenantId = "system"` operationally while the managed tenant is the aggregate ID, so helper APIs needed to make that distinction explicit.
- High-level test ergonomics and low-level conformance control pulled in different directions. The two-tier API resolved that tension cleanly.
- Date/time fields in domain events required special comparison behavior in conformance tests. Exact record equality is correct for most events, but timestamp-producing events need field-aware comparison.
- Reflection-based command discovery is powerful, but the expected-count assertion must be maintained intentionally when the command namespace changes.
- The Testing package can prove domain and projection parity, but it cannot prove ASP.NET host authentication, DAPR sidecar behavior, middleware ordering, or runtime topology. That boundary remained important from the Epic 5 retro.

Murat (Test Architect): "The lesson is not 'the fake replaces integration tests.' The lesson is 'the fake makes most behavior cheap to test, and conformance tells us when it stopped being faithful.'"

## Key Lessons

1. A fake earns trust by sharing implementation paths, not by mimicking behavior from memory.
2. Test ergonomics and conformance rigor need different APIs. Hiding envelopes helps consumers; accepting exact envelopes helps parity tests.
3. Reflection discovery is a useful guardrail only when paired with an explicit expectation that fails loudly.
4. Projection tests need the same reuse discipline as command tests. Reusing production read models avoids a second query semantics layer.
5. In-memory tests are not a substitute for host, DAPR, authentication, and topology tests. They are a fast inner loop with a clear boundary.
6. Retrospectives should keep old readiness defects visible even when the current epic succeeds technically.
