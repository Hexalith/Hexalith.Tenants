## Epic Summary

Epic 5 delivered the tenant-domain audit and forward-correction surface for FR20 through FR25. The work added user-facing evidence from existing tenant read/query behavior, kept audit and correction flows support-safe, and avoided new backend endpoint or event-history mutation assumptions.

The main implementation arc was:

- Story 5.1: tenant audit DataGrid backed by a tenant-scoped BFF query, with safe row projection and cursor recovery.
- Story 5.2: scoped audit entry points from tenant, user, member, command result, and navigation surfaces.
- Story 5.3: support-safe Audit Evidence Receipt construction from allow-listed row data.
- Story 5.4: shared audit availability state for pending, delayed, unavailable, and missing-support cases.
- Story 5.5: correction-start intent and a non-submitting panel, exposing the gap between model readiness and live-flow enablement.
- Story 5.6: preview and confirmation for tenant-domain correction with linked proof and projection-confirmed success.

## What Went Well

The team preserved the core audit invariant: accepted, projection-confirmed, and audit-available remained distinct states. SignalR stayed a nudge, not a proof source. The UI did not pretend that a submitted command was already visible in the durable audit trail.

The approved flat `FC-AUD` fallback became a real Tenants UI surface without pulling generic grid or shell scaffolding into the domain module. This kept the repository inside its domain responsibility boundary.

Support safety was handled as a layered concern rather than copy polish. Row allow-lists, receipt builders, classifiers, resource-backed messages, and static checks all contributed. Story review found and fixed several places where raw source-kind tokens or unsafe copy could leak through.

The review loop worked. Story 5.6 directly absorbed Story 5.5's high-risk follow-up around live correction enablement and resolved the tenant-domain side using role selection, current projection evidence, the existing command gateway, proof lookup, one-at-a-time locking, and localized conflict copy.

Test evidence grew with the behavioral surface. Story-level UI suites stayed green through the Epic 5 sequence, ending at 610/610 in Story 5.6. Later committed-state verification recorded all tiers green with 2115 passing and 0 failing.

## Challenges And Growth Areas

The 2026-06-06 Epic 5 retrospective aged out quickly because later Epic 4 command work changed the meaning of the global-administrator follow-up. The stale document was not wrong as a snapshot, but it no longer described the best next gate.

Story 5.5 was model-complete but not live-flow complete. That distinction was useful, but it needs to be explicit whenever a story adds state machinery without enabling the visible path that exercises it.

Copy and localization defects appeared repeatedly: source-kind token leakage, conflict text safety, and machine-ish snapshot labels. Audit and recovery surfaces are high-risk copy areas because one unsafe word can imply hidden rollback, event deletion, or broader support power than the system provides.

Global-administrator correction remains intentionally fail-closed. Epic 4 now provides grant/remove command primitives for the fixed `global-administrators` scope, but no Epic 5 story verified an enabled correction flow that selects that fixed scope and preserves last-admin safety.

Terminal correction focus behavior still has an accessibility gap. Close and cancel return paths are wired, but the confirmed/failed in-panel lifecycle state does not yet have programmatic focus movement and coverage strong enough to treat the issue as closed.

The correction status path still has a low-risk redundant projection refresh. It preserves correctness, but it is worth removing while keeping projection-confirmed success and proof lookup behavior intact.

## Significant Discovery

The key discovery is a dependency change:

Old framing: global-administrator correction is blocked because Epic 4 command support is missing.

Current framing: Epic 4 command support exists, but global-administrator correction must remain fail-closed until a focused story verifies the enabled correction path against the fixed `global-administrators` scope, platform-governance rejection copy, proof lookup, and last-admin safety.

That distinction matters because tenant-domain correction success is not enough evidence to infer global-administrator correction safety.
