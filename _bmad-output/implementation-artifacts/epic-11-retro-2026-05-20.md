- **Three-hunter code review (Blind Hunter + Edge Case Hunter + Acceptance Auditor) held on every story.** Patches landed inside AC scope, not outside. 11.3's Acceptance Auditor explicitly confirmed all 5 ACs satisfied with inherited contracts from 11.1/11.2 verified end-to-end. Review yield: 11.1 = 1 patch + 4 deferred; 11.2 = 15 patches (4 decisions + 11 patches) + 7 deferred; 11.3 = 18 patches (1 decision + 17 patches) + 3 deferred.
- **Composition-not-replacement pattern survived three stories.** 11.1's `ValidateTenantProductionAuthenticationOptions` registered as additional `IValidateOptions<EventStoreAuthenticationOptions>` beside the shared validator; 11.2 added `EventStoreClaimsTransformation` + claims-based validators beside existing JWT bearer registration; 11.3 added a smoke-side `JwtBearerOptions` post-configure seam beside production wiring. None became public API. The shared EventStore validator and JWT options configurator are unmodified.
- **Claim-contract idempotency was tested explicitly, not inferred.** 11.2 proved that an existing `eventstore:*` claim short-circuits source-claim merging in `EventStoreClaimsTransformation`. `BlankOrEmptyDirectEventStoreTenantClaimIsNotRepairedBySourceClaims` is now the contract: aliases cannot repair a blank or empty direct claim. 11.3 extended this with `\t`/`\n` rows so "whitespace fails closed" means actual whitespace categories, not just single-space.
- **Inherited contracts honored, not reopened.** 11.3 explicitly states "this story verifies and documents inherited contracts; it does not create new production JWT policy, tenant-claim semantics, live IdP provisioning, or production Keycloak/AppHost architecture." The prerequisite-contracts section made the boundary explicit and the Acceptance Auditor verified it held.
- **Failing-open defaults caught and flipped.** 11.2 P15 flipped `useTestAuthentication=true` to `false` in `CommandApiWebApplicationFactory`. Tests that previously inherited a TestAuth principal must now opt in explicitly. New tests inherit fail-closed behavior by default. This was a near-miss — the previous default could have masked auth regressions across the whole integration suite.
- **Theory expansion locked the parser contract.** 11.3's global-admin 10-shape theory (`global_admin=true`, `is_global_admin=true`, `role=GlobalAdministrator`/`global-administrator`, `roles`-array, boolean casing `"True"`/`"TRUE"`) and the non-global-admin deny-shape theory (`global_admin=false`/`""`/`"yes"`/`"1"`) explicitly pin "presence of claim is NOT bypass; only the truthy boolean-parser path elevates." A future IdP emitting `global_admin="yes"` as a string would not silently become a global admin.
- **Test-vs-runtime resolution gap closed.** 11.3 P6 replaced a fresh-options `MapInboundClaims` check with a real-HTTP request asserting the principal exposes raw `sub` (not `ClaimTypes.NameIdentifier`), so a future late `PostConfigure` flipping the flag after first-request resolution would fail. Same shape: 11.3 P7 replaced descriptor closure capture with `factory.Services.GetServices<IClaimsTransformation>()` enumeration after `CreateClient()` so a `services.Replace(...)` decorator registration cannot silently pass the "registered as Transient" assertion.
- **Documentation matured into two audience-appropriate surfaces.** Operator-facing readiness (`docs/production-auth-readiness.md`: checklist, evidence map, redaction rules, split 401 failure-triage rows by `WWW-Authenticate` shape) and IdP-integrator-facing claim contract (`docs/production-auth-claim-contract.md`: mixed-source precedence, direct-claim authoritative, rate-limit-not-enforced callout, command/query permission rows split with `LegacyQueryPermission` framing). Same underlying contract, two reading audiences. The Blind Hunter false-positive about "permission rows differ between docs" confirmed the split was intentional.
- **R9-A4 stayed resolved.** The unfiltered regression gate that turned green in Epic 10 (660 passed) grew through Epic 11 to 723 passed (+63 net) without re-introducing the AspireTopologyTests Docker/Redis blocker. The conformance fixture, optimistic concurrency policy, and cancellation taxonomy from Epic 10 remained intact.
- **Cancellation taxonomy preserved through claim-contract work.** 11.2's tenant-claim work could have caught `OperationCanceledException` and mapped it to a 401 or anonymous-bucket fallback. It didn't. The Epic 10 contract is intact end-to-end: cancellation remains distinct from `Forbidden`, `Invalid cursor`, `Tenant not found`, generic actor failure, ETag conflict, and retry exhaustion.

## Key Lessons

1. **Composition beside the shared validator, not in place of it, is the right shape for host-specific policy.** `ValidateTenantProductionAuthenticationOptions` registered as additional `IValidateOptions<EventStoreAuthenticationOptions>` beside `ValidateEventStoreAuthenticationOptions` lets `ValidateOnStart` evaluate the composed policy without forking shared infrastructure. The shared EventStore validator stayed unmodified across three stories.
2. **`EventStoreClaimsTransformation` idempotency means aliases cannot repair direct claims.** A direct `eventstore:*` claim — even empty or whitespace — short-circuits source-claim merging. Operators emitting both direct and source tenant claims will get the direct claim only. Tests must inspect the effective downstream principal after transformation, not the raw JWT payload.
3. **`useTestAuthentication=true` was failing-open by default.** A test fixture that defaults to bypassing real JWT bearer middleware while exercising "production" auth paths is the most dangerous shape: every test inheriting the default looks like it proves auth wiring and proves nothing. 11.2 P15 flipped it to `false`. Any future test-fixture default that bypasses production middleware must opt in explicitly.
4. **Theory-row expansion is the test-side analogue to AC density.** 11.3's global-admin 10-shape theory, non-global-admin deny-shape theory, BlankOrEmpty tab/newline rows, and null/empty Authority theory turned implicit assumptions into explicit parameterized contracts. A new shape that should fail closed cannot be silently accepted; a new shape that should be accepted cannot be silently rejected.
5. **Test-vs-runtime resolution gaps are catchable.** Fresh-options `MapInboundClaims` checks pass even if a late `PostConfigure` flips the flag after first-request resolution. Descriptor closure captures pass even if a `services.Replace(...)` decorator changes the registration after build. 11.3 P6 and P7 replaced both with materialized-provider assertions. This is the test-side equivalent of "observe production behavior, do not reimplement it."
6. **Documentation needs audience separation, not consolidation.** Operator-facing readiness and IdP-integrator-facing claim contract have different reading audiences and different "correct level of detail." The Blind Hunter false-positive about "permission rows differ between docs" confirmed the split was the right call. Same contract, two surfaces.
7. **`ClockSkew = TimeSpan.Zero` is contract-critical, not stylistic.** Default 5-minute skew silently extends expired tokens. Production smoke tests with expired tokens must pin zero skew explicitly, or use `expires: DateTime.UtcNow.AddHours(-1)` to fall clear of the default. 11.3 P16 made the expired-token edge unambiguous.
8. **401 failure modes are not interchangeable.** Missing token, expired token, invalid signature, wrong issuer, and wrong audience all produce 401, but they produce distinct `WWW-Authenticate` `error_description` values. Tests that assert only status code miss regressions where wrong-audience starts producing the same code as expired. 11.3 P5 added the distinction.
9. **`LegacyQueryPermission` exists because the IdP sample emits it.** Removing `command:query` from the docs without removing it from the Keycloak realm sample would have made the doc lie. Keeping it without tightening the framing would have invited new IdPs to propagate the legacy shape. Patch P18 found the right middle: keep the row, name the validator constant, point at `hexalith-realm.json` as origin, recommend `query:read` for new IdPs.
10. **The deferred-work pattern is now self-similar across three epics.** Items added > items drained, every epic. The list is becoming a risk register, not an action list. Jerome's R11-A1 decision (assign owners + deadlines now) is the first attempt to flip that.

## Significant Discoveries

- **`EventStoreClaimsTransformation` is idempotent on the principal, not on the raw token.** Existing `eventstore:*` claims short-circuit alias/source merging entirely. An IdP that emits both `eventstore:tenant=""` AND `tenants=["system"]` will produce a principal with `eventstore:tenant=""` only — the source claim is not used to repair the blank direct claim. This is permanently load-bearing for any future cross-claim-shape mapping work; documented in `docs/production-auth-claim-contract.md` mixed-source precedence section.
- **`useTestAuthentication=true` as a default was failing-open across the integration suite.** Every test inheriting the default bypassed real JWT bearer middleware while running through "production" auth paths. 11.2 P15 flipped to `false`. The previous default could have masked auth regressions for an unknown number of pre-Epic-11 test runs. Defaults that bypass production middleware must opt in explicitly.
- **The Tenants host wires authorization without the EventStore rate limiter on purpose.** Adding `EventStoreClaimsTransformation` + `AuthorizationBehavior<,>` + claims-based validators does NOT require `AddEventStore()` (the full server extension). The narrow registration is the right shape; calling out "rate limiter not registered" in the IdP-integrator doc is what prevents operators from assuming partitioning works here.
- **`LegacyQueryPermission` is a real validator constant, not a documentation typo.** Verified at `ClaimsRbacValidator.cs:22,63-68`: `command:query` is accepted via the explicit `LegacyQueryPermission = "command:query"` constant with `string.Equals(p, LegacyQueryPermission, StringComparison.OrdinalIgnoreCase)`. The validator's own XML doc names it as "legacy permission still used by the local Keycloak realm." 11.3 P18 tightened the doc framing rather than removing the row or pretending it didn't exist.
- **`ClockSkew = TimeSpan.Zero` is contract-critical for expired-token rejection.** Default 5-minute clock skew silently extends expired tokens past their `exp` claim. The smoke fixture sets zero skew explicitly; if a future refactor lifts `ClockSkew` out of `TokenValidationParameters` into a `JwtBearerOptions` shadow property, the default 5-minute skew silently returns. Tests that need to assert expiration should use `expires: DateTime.UtcNow.AddHours(-1)` to fall clear of any default skew, or explicitly assert `JwtBearerOptions.TokenValidationParameters.ClockSkew == TimeSpan.Zero`.
- **401 cases produce distinct `WWW-Authenticate` `error_description` values.** Missing token, expired token, invalid signature, wrong issuer, and wrong audience all produce 401, but the handler emits different `error_description` values. Tests that assert only status code miss the failure-mode distinction. The Failure Triage table in `docs/production-auth-readiness.md` now splits 401 by `WWW-Authenticate` shape (expired, invalid signature/issuer/audience, missing).
- **`IClaimsTransformation` ASP.NET Core lifetime is per-request Transient.** A future change to Singleton or Scoped would silently pass a registration-existence test but break the per-request re-invocation contract. 11.2 P8 pinned the lifetime assertion; 11.3 P7 extended it to enumerate `factory.Services.GetServices<IClaimsTransformation>()` so a `services.Replace(...)` decorator is not invisible.
- **`MapInboundClaims` must be verified host-effectively, not on fresh options.** A future late `PostConfigure` that flips the flag after first-request resolution would silently pass a fresh-options check. 11.2 P9 / 11.3 P6 added a real-HTTP request asserting the principal exposes raw `sub` (not `ClaimTypes.NameIdentifier`).
