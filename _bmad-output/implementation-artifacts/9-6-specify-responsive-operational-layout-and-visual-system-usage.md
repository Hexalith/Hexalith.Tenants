# Story 9.6: Specify Responsive Operational Layout and Visual System Usage

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a UI implementer,
I want responsive and visual-system rules for operational screens,
so that dense access-review workflows remain usable without sacrificing truth or context.

## Acceptance Criteria

1. **Given** visual system usage is specified, **when** tenant-specific meaning is mapped to UI treatment, **then** tenant status, projection freshness, command lifecycle, authorization state, audit evidence, and risk use semantic roles instead of hard-coded colors, **and** every state remains understandable without color alone.
2. **Given** typography and layout rules are specified, **when** operational screens are implemented, **then** they use professional, calm, precise system typography, compact density, modest hierarchy, and plain-language status labels, **and** decorative card grids or hero-scale type are avoided for dense operational workflows.
3. **Given** command and status layout is specified, **when** toolbars, status chips, action cells, and lifecycle panels render, **then** stable dimensions prevent layout shift, **and** command controls remain close to the affected tenant, user, role, or audit context.
4. **Given** responsive behavior is specified, **when** screens render at desktop, tablet, and mobile widths, **then** desktop remains the primary workstation layout, tablet may collapse navigation and stack regions, and mobile is limited to read-only triage, lookup, and audit reference review, **and** high-impact access changes fail closed or become unavailable when full safety context cannot be preserved.
5. **Given** breakpoint guidance is documented, **when** implementation stories define layout tests, **then** mobile 320-767px, tablet 768-1023px, desktop 1024px and above, and wide desktop 1440px and above are covered, **and** DataGrid horizontal scroll or column priority preserves critical state instead of hiding it.

[Source: `_bmad-output/planning-artifacts/ux-design-specification.md#Color System`; `docs/tenants-ui-truth-state-and-action-availability-spec.md` §2.3; `docs/tenants-ui-frontcomposer-dependency-map.md#FC-TOK`]
- **Typography & layout (AC2):** professional/calm/precise system typography, compact density (4px rhythm), modest hierarchy, plain-language status labels; tables/split views/tabs/side panels/dialogs/inline status over decorative card grids; no hero-scale type for dense workflows. [Source: `_bmad-output/planning-artifacts/ux-design-specification.md#Typography System`; `#Spacing & Layout Foundation`]
- **Command/status layout (AC3):** stable dimensions for status chips, action cells, toolbars, and lifecycle panels prevent layout shift; command controls stay close to the affected tenant/user/role/audit context (9.3 proximity placement; lifecycle inside the workflow, not a separate nav area). [Source: `_bmad-output/planning-artifacts/ux-design-specification.md#Spacing & Layout Foundation`; `docs/tenants-ui-truth-state-and-action-availability-spec.md` §6.1; `docs/tenants-ui-operations-shell-spec.md` §1.2]
- **Responsive behavior (AC4):** desktop-first primary workstation layout; tablet collapses navigation and stacks regions (table usability via horizontal scroll / column priority / row-detail expansion); mobile is read-only triage/lookup/audit reference only; high-impact changes fail closed or become unavailable when full safety context cannot be preserved (truth over compactness). [Source: `_bmad-output/planning-artifacts/epics.md` UX-DR65–UX-DR68; `docs/tenants-ui-truth-state-and-action-availability-spec.md` §3.3/§4.3]
- **Breakpoints (AC5):** mobile 320–767px, tablet 768–1023px, desktop 1024px+, wide desktop 1440px+; DataGrid horizontal scroll or column priority preserves critical state instead of hiding it. [Source: `_bmad-output/planning-artifacts/epics.md` UX-DR69; `_bmad-output/planning-artifacts/ux-design-specification.md#Search, Filtering, and Table Patterns`]
- Custom components this spec *governs but does NOT implement*: the visual semantic-role/status treatment across the Truth State Badge, Freshness Gate, Unavailable Action Reason, Command Lifecycle Panel, Consequence Preview, Audit Evidence Receipt, and Flat Audit List Fallback (all referenced from 9.2/9.3/9.5, not redefined), plus the responsive layout behavior of the Operations Shell and all read-only/command surfaces. [Source: `_bmad-output/planning-artifacts/ux-design-specification.md#Custom Components`; `docs/tenants-ui-frontcomposer-dependency-map.md#Dependency ID Catalog`]
