## Scope Completed

- Story 9.1: Data Protection-backed `TenantQueryCursorCodec` with versioned purpose `Hexalith.Tenants.QueryCursor.v1`, endpoint scope helpers (`list-tenants`, `get-tenant-users`, `get-user-tenants`, `get-tenant-audit`), controller-level invalid-cursor ProblemDetails, actor-level invalid-cursor handling, and structured `failureReason` logging. Cursor length capped at 4 KB; `pageSize` JSON parses through `TryGetInt32`.
- Story 9.2: Ordinal keyset continuation with exclusive lower-bound advancement, mutation-between-pages test coverage (revoked role, demoted owner, newly visible tenant, target-user removal), and `EscapeSegment` over `:|\` in cursor scope helpers to remove a delimiter-collision risk.
- Story 9.3: Pre-pagination orphan filter on `get-user-tenants`, structured projection-repair warning (EventId 1903) with per-actor in-memory dedup keyed by `(targetUserId, orphanTenantId)`, disabled-tenant visibility preserved with `TenantStatus.Disabled`, eventual-consistency documentation in `docs/cross-aggregate-timing.md`, and removal of the empty-name/active fallback.
- Story 9.4: Actor-layer guard on null/empty/whitespace `UserId` for the five role-sensitive query types, ordered before authorization lookup, cursor parsing, payload parsing, and state reads; `Forbidden` mapping reuses existing EventStore adapter semantics; AC8 mixed-failure precedence test pins the order.
- Story 9.5: Internal `TenantQueryPaginationPolicy` (`StandardDefaultPageSize=20`, `StandardMaximumPageSize=100`, `AuditDefaultPageSize=100`, `AuditMaximumPageSize=1000`) plus `TenantQueryPaginationPayloadParser` replacing duplicate clamp helpers in controller and actor; non-object JSON root now returns the documented default first page instead of throwing.

Epic status in `sprint-status.yaml`: stories all `done`, epic still flagged `in-progress` because the retrospective key (`epic-9-retrospective`) was `optional`. This retrospective settles the optional gate.

## What Went Well

- One signed-cursor design, one scope helper, one pagination policy. Controller and actor share the same source of truth across four endpoints. Defense in depth is intentional: actor-layer checks still run even though controller validates first, because actor proxy access remains possible.
- Each story passed through the same pre-dev pattern before any code changed: `bmad-party-mode` review with Winston/Amelia/Murat/John, then `bmad-advanced-elicitation` with two reshuffled method batches. That tightened acceptance criteria before red-phase tests and visibly reduced the volume of late-stage corrections.
- Code review depth held across the epic. Blind Hunter / Edge Case Hunter / Acceptance Auditor produced concrete findings: 9.1 applied 11 patches plus 5 deferred; 9.2 applied 4; 9.3 applied 5; 9.4 applied 1; 9.5 applied 5. Findings were triaged into patch / defer / dismiss with reasoning, not blanket-applied or hand-waved.
- Cursor opacity tests were strengthened beyond "substring is absent". 9.2's patch made the tests build a codec, call `TryDecode`, and assert the decoded inner position matches the expected key. That is the right shape: prove the codec round-trips, not that a string omits a guess.
- Story 9.4 added a single mixed-failure precedence test (`list-tenants` invalid cursor + malformed user) to pin the ordering. One precedence test is more valuable than five isolated rejection tests for a defense-in-depth contract.
- Failures kept producing structured information without leaking secrets. EventId 1902 (invalid cursor) carries `TenantId`, `UserId`, `FailureReason`, correlation ID. EventId 1903 (orphan membership) carries correlation ID, requester, target user, orphan tenant ID, stage. Client-facing message stays opaque (`"Invalid cursor."`); operators get the diagnostic detail.
- Scope discipline held except where it was explicitly relaxed. Stories repeatedly said "no `Hexalith.EventStore` submodule changes, no `QueryEnvelope` constructor change, no route or DTO change". The one relaxation (9.5's submodule pointer bumps + `global.json` SDK pin to 10.0.300) was retroactively approved through SCP-2026-05-18-latest-dotnet rather than silently merged.
- Eventual-consistency behavior is documented as an accepted policy, not a bug. Story 9.3 added the stale-self-lookup regression guard proving the brief membership-removal window grants no write capability.

Murat (Test Architect): "The pattern I want preserved into Epic 10 is the order: party-mode → advanced elicitation → red tests → implementation → code review with all three hunters. Every story in Epic 9 followed it and every story has the review findings to show for it."

## Challenges

Charlie (Senior Dev): "Epic 9 also exposed where the verification environment is the bottleneck."

- The mandatory unfiltered regression gate failed on every story for reasons unrelated to the story code. The recurring offenders were `AspireTopologyTests` (Docker Desktop unhealthy or Aspire `AppHost` version drift), `SnapshotPerformanceTests.ColdStartRehydration_CompletesWithin30Seconds_With500KEvents` (configuration-limit rejection during seeding), and DAPR-backed integration tests requiring Redis on `localhost:6379`. Story 9.1 closed its specific blocker by gating the 500k-event seed behind `HEXALITH_TENANTS_RUN_PERFORMANCE_TESTS=1`, but 9.2 through 9.5 still hit Docker/Redis prerequisites at developer-machine scope.
- Cursor scope helpers had a quiet delimiter-collision risk. `TenantQueryCursorScopes` used `|` as a segment separator but did not escape `|`, `:`, or `\` in caller-supplied values. The Edge Case Hunter caught it in 9.2; if tenant or user IDs had ever contained those characters in production, cross-endpoint cursor reuse could have looked valid. Fixed by `EscapeSegment` and locked in by tests across all four helpers.
- The original cursor decoder discarded `failureReason` and only returned `false`. Reviews on 9.1 and 9.2 surfaced this independently. Resolved by promoting `failureReason` to a structured field on EventId 1902 with codes (`malformed`, `wrong-query-type`, `wrong-scope`, `wrong-version`, `empty-position`, `too-large`, `tamper-or-key-rotation`). The client-facing message stayed opaque; the operator-facing detail got recovered.
- Story 9.1's `correlationId` was disconnected from the W3C trace context. The fix sourced it from `Activity.Current?.Id ?? HttpContext.TraceIdentifier` and shared it between the rejection log and the downstream `SubmitQuery`. Distributed correlation now actually correlates.
- `EphemeralDataProtectionProvider` in tests means cross-replica/multi-host Data Protection key sharing for cursors is unverified in production-like topology. Deferred to Epic 11; called out at the time so it would not get lost.
- Story 9.5 carried a scope violation (submodule pointer bumps for `Hexalith.EventStore`, `Hexalith.Commons`, `Hexalith.FrontComposer`, and `global.json` SDK 10.0.103 → 10.0.300). It was retroactively approved through SCP-2026-05-18-latest-dotnet, but the pattern matters: cross-cutting infra changes piggybacking on a refactor story bypass the planning gate that would normally call them out.
- Several deferred items accumulated rather than resolved inside the epic: `_loggedOrphanMemberships` HashSet unbounded per actor lifetime (9.3 → deferred), `EntityId` whitespace silently coerces to self-lookup (9.3 → deferred, pre-existing), `pageSize` not bound to cursor scope (9.1 → deferred), cursor `IssuedAt` encoded but never validated (no expiry policy yet → deferred to Epic 11). The deferred list is honest but it is also growing.
- Predev preflight tooling commits absolute Windows paths (`D:\Hexalith.Tenants\...`) into `_bmad-output/process-notes/` and `predev-preflight-latest.json` is overwritten between runs, capturing intermediate dirty-tree state as `result: fail`. Pre-existing, deferred, but visible in this repository's git noise.

Winston (Architect): "The cursor codec design is sound. The risks left are operational: durable key persistence in production, key rotation strategy, cursor expiry. None of those undo the epic; all of them are real before deployment."

## Key Lessons

1. The party-mode review → advanced-elicitation → red tests → implementation → three-hunter code review sequence is now a load-bearing process invariant, not a ceremony. Every Epic 9 story followed it, and every story has documented findings that would not have surfaced otherwise.
2. Defense in depth pays for itself. Controller validates the cursor, the actor revalidates the cursor; controller clamps page size, the actor clamps page size; controller authenticates, the actor rejects malformed `UserId`. Each duplication was paid back at least once during review.
3. Failure metadata is part of the contract. Returning `false` from a decoder is half a contract; returning `(false, failureReason)` and emitting a structured log lets operators diagnose without forcing the client-facing error to leak.
4. Delimiter and encoding boundaries deserve explicit escape, even for "internal" helpers. `|`-separated scope strings looked safe until the Edge Case Hunter asked what happens when a tenant ID contains `|`.
5. Cursor opacity tests should prove round-trip semantics, not substring absence. A protected token will inevitably encode the inner key as bytes; the question is whether `TryDecode` re-derives the expected position, not whether you can grep for the user ID.
6. Environmental gates (Docker, Redis, Aspire AppHost versions, performance seed limits) keep blocking the unfiltered regression run. The current workaround is per-story environment skips; the next step is making the topology gate self-healing or explicitly opt-in.
7. The deferred-work list is information, not failure. But it grows monotonically unless an epic exists to drain it. Epic 11 inherits cursor expiry, durable DP keys, and the unbounded `_loggedOrphanMemberships` set; Epic 10 inherits cancellation threading and projection write conformance. Both lists need owners before those epics close.
8. Cross-cutting infra changes (submodule bumps, SDK pins) should not piggyback on a refactor story even with retroactive approval. The right pattern is the explicit sprint-change proposal first; the wrong pattern is the SCP catching up to merged work.

## Critical Path Items

- Do not start Story 10.3B cancellation threading until Story 10.3A merges the cancellation-aware EventStore projection contracts. The dependency is technical and named; do not invent Tenants-local cancellation infrastructure as a workaround.
- Do not claim production cursor durability until Action R9-A2 (durable DP key persistence) is wired.
- Do not claim production-ready release until cursor expiry policy (Action R9-A1) is settled, even if the encoded field stays unvalidated as a deliberate decision.
- Do not let Epic 9's deferred-work list cross over into Epic 11 unread. Action R9-A7 prevents that.
- Do not weaken Epic 9's guard ordering when adding cancellation, retries, or projection write concurrency. The actor-layer malformed-`UserId` rejection must remain the first observable result on role-sensitive query envelopes.

## Significant Discoveries

- The `EntityId` whitespace coercion to self-lookup (`TenantsProjectionActor.cs:398`) is pre-existing, not introduced by Epic 9, but is now visible because Story 9.3's orphan warnings include the target user. Whitespace `EntityId` mislabels cross-user intent and obscures orphan-warning fidelity. Tracked as deferred; should be re-evaluated before public release.
- `EphemeralDataProtectionProvider` is used in every cursor test. That makes the production cross-replica / multi-host DP key-sharing path unverified by the focused suite. This is a known gap, deliberately deferred to Epic 11. It is the single largest hidden risk in the Epic 9 deliverable.
- Cursor `IssuedAt` is encoded by `TenantQueryCursorCodec` but never validated. There is no expiry, no skew tolerance, no rotation forcing. This is fine for current behavior because cursors are short-lived in practice, but it is a contract the codec already advertises and silently ignores.
- The Aspire `AppHost` version requirement drifted between story 9.1 and the rest of the epic (`13.3.2` minimum surfaced from `AspireTopologyTests` failures). The fix landed via SCP-2026-05-18-latest-dotnet, but the discovery itself shows the AppHost version is a latent dependency that breaks the topology suite when it slips behind the integration test expectations.
- The Story 9.4 implementation commit (`1275e8d`) carries a misleading commit title ("Add preflight check results for multiple timestamps with failures"). The code review caught and recorded this. The commit message convention (Conventional Commits) was followed in spirit elsewhere; this is an outlier worth flagging because semantic-release uses commit messages to drive version bumps.
