## What Went Well

- The AppHost story corrected the runtime proof gap from earlier epics. The Sample consuming service is now part of the local topology, so event subscription behavior is visible through the same orchestration path developers use.
- The Aspire extension stayed small and composable. The Tenants service gets state store and pub/sub references, while the Sample subscriber gets only the pub/sub reference it needs.
- Telemetry was intentionally bounded. Tenant IDs live on spans, not metric dimensions, and command/query metric labels are sanitized to avoid cardinality problems.
- The health-check design found a clean signal: one DAPR state-store probe verifies sidecar and backing store reachability without duplicating liveness checks.
- Story 7.3 treated statelessness as something to prove, not merely claim. The epic now has evidence for configuration, actor reactivation behavior, degradation behavior, and scale-oriented snapshot assumptions.
- Follow-up review on telemetry caught real quality risks: global listener contention in tests, Activity disposal ordering, EventStore source registration, query metric sanitization, and failure-path query spans.

## Challenges

Charlie (Senior Dev): "Epic 7 looked like operations plumbing, but every story touched a boundary where false confidence is easy: topology, telemetry, readiness, and infrastructure recovery."

- The AppHost and Aspire testing work exposed a recurring theme: infrastructure behavior cannot be honestly verified with only unit tests or in-memory fakes.
- Telemetry tests share global .NET listeners, so tests needed serialization and careful assertion targeting. That is easy to miss and can create flaky evidence.
- Activity lifetime needed manual care. Setting tags after an Activity was disposed hid expected values, so the implementation had to keep disposal under explicit control.
- Metric labels required threat-modeling. Raw user-controlled command/query names are convenient but unsafe as aggregation dimensions.
- Graceful degradation verification depends on EventStore testing infrastructure. The story had to validate Tenants behavior without changing the EventStore submodule.
- Story artifacts contain some specification drift. Epic 7 and Epic 8 records both document places where the original plan assumed manual DAPR/Keycloak or different AppHost behavior, while implementation correctly followed the actual Tenants topology.

Murat (Test Architect): "The lesson is not 'add more tests.' The lesson is 'name what each test proves.' Topology, telemetry, health, and snapshots each have different failure modes."

## Key Lessons

1. Runtime topology deserves first-class verification. AppHost and DAPR sidecar behavior are product behavior, not setup trivia.
2. Observability code needs its own quality discipline. Metric cardinality, span lifetime, failure tagging, and listener isolation can all become production or test defects.
3. Health checks should report actionable dependency state without turning every readiness problem into a restart signal.
4. Stateless architecture is only credible when restart, snapshot, and degradation behavior are represented in the evidence set.
5. Documentation must follow implemented topology, not stale assumptions from earlier planning.
6. Carry-forward defects should stay loud until sprint status proves they are resolved or intentionally deferred.
