## Intent

**Problem:** Nine open deferred-work items span five independent slices: (1) UI principal corroboration and FrontComposer command authorization races/uncooperative waits (`DW-674`, `DW-693`, `DW-694`), (2) rejection-only tenant recovery verification (`DW-700`, already fixed on `main` in `8aa6f169` without an SDK-replay assertion), (3) `Hexalith.Tenants` host bypassing the `5.3.0+` EventStore snapshot-budget build floor (`DW-680`, duplicate `DW-699`, already fixed on the 5 packages), (4) missing multi-row protected cursor continuation and cross-query refusal tests for global-administrator audit (`DW-689`), and (5) uncooperative enrichment tasks hanging `TenantQueryGateway.EnrichRowsAsync` plus assessment of its 90-second budget (`DW-675`, `DW-685`).

**Approach:** Implement each of the five batches in parallel via dedicated subagents, verify with the full build and test suite plus repository checks, update the deferred-work ledger (preserving existing 2026-11-27 archive edits), and push directly to `main`.

**Approved Decisions:**
- **DW-693 & DW-694 (FrontComposer submodule):** Implement and test both inside `references/Hexalith.FrontComposer`, commit and push `Hexalith.FrontComposer` `main` first, then update the submodule pointer in Tenants.
- **DW-685 (90s enrichment budget):** Retain the 90-second default enrichment upper bound (preserving live 20-row CI and 75s/90s test expectations), close `DW-685` with recorded assessment, and add an opt-out (`TenantListRequest.IncludeRowEnrichment = true` default; `TenantSummaryProjectionPage` passes `false`) so callers that never display member/owner counts skip unneeded detail enrichment without degrading.
- **Scope/Spec Size:** Keep all five batches together in this spec (~3,200 tokens, above the 1,600 guideline) with one focused subagent per batch.
