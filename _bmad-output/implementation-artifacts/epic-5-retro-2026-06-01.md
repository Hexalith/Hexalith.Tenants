## Key Learnings

1. Evidence-hardening stories need the same rigor as runtime-change stories. They often uncover metadata, test, and documentation drift.
2. Query-side authorization must filter before pagination and before cursor metadata is produced. Hidden rows must not influence `items`, `cursor`, or `hasMore`.
3. Default enum values are security-relevant. `TenantRole.Unknown` must remain non-privileged and invisible in query DTOs.
4. DAPR component names are implementation contracts. Planning docs that name a different state store can mislead projection work even when source code is correct.
5. Audit rows need explicit support-safe fields for UI and operations. Relying only on `narrativePayload` makes the API harder to consume and under-specifies the contract.
6. Global-administrator events belong in the audit model too, but under system scope. Story 5.10 made that path explicit with `audit:system`.

## Next Epic Preview

Epic 6: Developers Can Test Tenant Behavior Without Infrastructure

Epic 6 builds on Epic 5 but has a different proof boundary:

- Epic 5 proves server projections, query authorization, cursor behavior, and audit query contracts.
- Epic 6 should provide in-memory fakes that execute production-equivalent aggregate logic without live DAPR, Aspire, Docker, or EventStore infrastructure.
- The Testing package can prove domain/fake parity and help consumer isolation tests, but it must not be presented as proof of ASP.NET authentication, DAPR sidecars, actor routing, or deployed Data Protection key-ring behavior.

Epic update required: No.

The Epic 6 purpose remains sound. The main carry-forward is documentation clarity: in-memory tests should state exactly what they prove and what remains integration/deployment evidence.
