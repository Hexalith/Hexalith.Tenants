## What Went Well

- `InMemoryTenantService` stayed command-driven and infrastructure-free while returning the canonical EventStore `DomainResult`.
- The fake delegates tenant commands to `TenantAggregate.Handle(...)`, global-administrator commands to `GlobalAdministratorsAggregate.Handle(...)`, and applies success events through production state `Apply(...)` methods.
- Story 6.2 proved the explicit-envelope path honors `CommandEnvelope.AggregateId`, so command payload tenant IDs cannot override production identity semantics.
- Story 6.3 turned fake parity into executable policy by discovering all command contracts and requiring intentional scenario coverage.
- Projection conformance now enumerates non-rejection success events and fails when `InMemoryTenantProjection` lacks explicit behavioral coverage.
- Story 6.4 added `TenantIsolationTestHelpers` for multi-tenant setup, tenant-scoped event replay, duplicate delivery simulation, role maps, lifecycle state, and revocation scenarios.
- The quickstart contains a copyable consumer-isolation example and states the aggregate-vs-consumer responsibility boundary.

## Key Learnings

1. A test fake is only trustworthy when it shares production decision points, not when it imitates production from copied rules.
2. Exact envelope control belongs in the low-level fake API because aggregate identity is security-relevant.
3. Conformance tests need explicit coverage data, not only method names or expected counts.
4. Safe test failure output matters. A conformance suite can be technically correct and still unsafe if failure details echo sensitive payload data.
5. Consumer-isolation helpers should emit and select tenant events; they should not pretend to validate a consumer's local projection or query model.
6. Documentation must name the confidence layer: fake, conformance, host integration, or topology.
