## 2026-06-02 — DESIGN: Layout contract (FC-LYT) → full-width
- **Decision:** spines state **full-width operational surfaces** (tables/work areas span the viewport; safety-critical columns — identity, status, freshness, role, risk — never drop).
- **Rationale:** dense admin workstation; full-width best satisfies "safety-critical columns never hidden" + compact-density preference; least horizontal-scroll risk.
- **Caveat:** FC-LYT is `needs-confirmation` — this is the UX *intent*; FrontComposer must confirm the shell supports full-width with constrained inner regions for forms/previews. Recorded as needs-confirmation, NOT "given" (corrects PRD §11 prose vs addendum; depmap Gap 2).

## 2026-06-02 — Reference: verified Fluent UI Blazor v5 vocabulary (MCP pkg 5.0.0.26139 ≈ PRD addendum rc.3-26138.1)
Grounds the DESIGN.md semantic-role mapping so no unavailable token is asserted:
- **BadgeColor:** Brand · Danger · Important · Informative · Severe · Subtle · Success · Warning (the status palette).
- **BadgeAppearance:** Filled · Outline · Ghost · Tint. **BadgeShape:** Circular · Rounded · Square. `FluentBadge` supports `IconStart`/`IconEnd` + `IconLabel` (aria) → enables no-color-only (color + icon + text in one component).
- **MessageBarIntent:** Success · Warning · Error · Info · Custom (note: MessageBar says "Error", Badge says "Danger"). **MessageBarLayout:** SingleLine · MultiLine · **Notification** (title/message/actions stacked — fits Command Lifecycle Panel + Audit Evidence Receipt). MessageBar sets aria-live by intent.
- **AriaLive:** Off · Polite · Assertive → implements the PRD live-region politeness rule (Assertive reserved for rejection / failure / unable-to-verify / destructive-block).
- **DataGridColumnPin:** pinned columns stay visible during horizontal scroll → the mechanism for "safety-critical columns (identity/status/freshness/role/risk) never drop" under full-width.
- Caveat: the generic `Color` enum carries a library TODO ("validate if still valid") — prefer `BadgeColor` semantic names; verify exact token CSS values against the pinned package at build.

## 2026-06-02 — DESIGN: status semantic mapping (meaning → Fluent BadgeColor) locked
- **3-tier caution ramp:** Warning (aging, timeout, audit delayed) → Severe (stale, tenant disabled, audit unavailable) → Danger (rejected, failed, high risk).
- **Locked invariant (honesty firewall):** Success is reserved for PROVEN truth only — freshness `current`, command `confirmed`, `audit available`, tenant `active`. Every in-flight state (`accepted`, `submitted`, `previewed`, `projection pending`, `audit pending`, `refreshing`) → **Informative**, never Success. Enforces CP-3 in color.
- Full role table: Success / Informative / Warning / Severe / Danger / **Important** (freshness `unknown` · lifecycle `unknown` · authorization `blocked`) / **Subtle** (`eligible` · `already applied` · `duplicate` · low risk · `missing implementation support` · not-yet-available) / **Brand** (chrome & primary action only, NEVER status).
- **No-color-only:** every status = `BadgeColor` + `IconStart` + `IconLabel`/text. Appearance: `Tint` default (calm), `Filled` for Danger/Severe.
- **Live regions:** `AriaLive.Assertive` for Danger + `unable to verify` + destructive-block; `Polite` otherwise.
- Inline status = `FluentMessageBar` (`MessageBarLayout.Notification`); MessageBar intent "Error" == badge "Danger" (don't unify token names).
- Bind to semantic roles, never hex; verify exact token CSS values vs pinned package at build.

## 2026-06-02 — Bake-in / defer defaults (non-blocking; logged, not separately elicited)
- **Identifiers (#12):** TenantId / UserId are meaningful caller-supplied strings, NOT ULIDs. "Copy full id" (FR-7) copies the literal string; never `Guid.TryParse`/`Ulid.TryParse`. Corrects the source-spec ULID error.
- **Cursors (#7):** opaque, signed, scope-bound, session-scoped; never offset/limit. On cursor invalidation, re-query from the first page with an honest "list refreshed" notice, not an error. (Cross-replica durability is a backend epic; UI doesn't assume cursors survive restarts.)
- **Freshness thresholds (#10):** numeric `current`/`aging`/`stale` cutoffs deferred to implementation + ops input; UX requires them configurable and surfaced honestly (state badge + absolute timestamp; `unknown` when unmeasurable). No magic numbers in the spine.
- **Sensitive configuration values (#11):** out of v1 read scope; values shown only for authorized prefixes, sensitive values masked/omitted until a future authZ-gated decision.
- **Command endpoint (#1):** UI treats the command route as configuration (default `POST /api/v1/commands`; tolerate `/api/commands` alias) — not a UX decision.
- **Localization resource ownership (#4):** flagged to architecture (shared FrontComposer shell resources vs Tenants-owned keys). UX constraint recorded regardless: whole-string resources with named placeholders, NO runtime sentence-fragment assembly; all listed surfaces localizable + culture-aware. Ownership to resolve with the shell/FrontComposer team.
