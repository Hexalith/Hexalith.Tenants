# Spine Pair Review (Rubric Walker) — Tenants Management UI

**Reviewed:** `DESIGN.md` + `EXPERIENCE.md` under `ux-designs/ux-tenants-2026-06-02/`
**Against:** `references/validate.md` (rubric), `references/design-md-spec.md` (DESIGN.md spec), `.decision-log.md`, `.working/prd-ux-digest.md`
**Run at:** 2026-06-02

## Verdict (one paragraph)

This is a strong, unusually disciplined spine pair: the honesty-firewall (`Success` = projection-proven only) is enforced at the color layer and restated consistently across both files; the canonical state vocabularies are reproduced verbatim with casing preserved and the spaced-vs-underscore duplication deliberately *not* unified; all ten domain components have full parity between `DESIGN.md` frontmatter/`Components` and `EXPERIENCE.md` `Component Patterns`; every DESIGN `{colors.*}`/`{spacing.*}`/`{typography.*}`/`{components.*}` reference resolves to a defined token; section order is canonical in both files; and the deferrals (freshness thresholds, l10n ownership, RTL, FR-22/24/25 backlog gap, FC readiness) are honestly flagged rather than invented around. The core product invariants (proven-firewall, non-collapse, correct-forward-never-undo, one-at-a-time, honest fallbacks) all hold. The defects are not structural — they are an internal undercount where `EXPERIENCE.md` claims the truth-state-badge renders "one of the 13 canonical states" while `DESIGN.md`'s own icon table maps ~30 distinct state tokens spanning six vocabularies (the single most-likely-to-mislead-a-consumer contradiction); a `risk` column and `risk high`/`risk low` badge bindings that no surface actually lands or defines; and a handful of DESIGN icon-table state→role bindings (`degraded`→Severe, `unable to verify`→Important, `previewed`→Informative, `disabled`→Severe) that the Colors *prose* never enumerates, so the prose is less complete than the table a consumer would mirror. None is a Blocker; the badge-13 contradiction is the must-fix.
