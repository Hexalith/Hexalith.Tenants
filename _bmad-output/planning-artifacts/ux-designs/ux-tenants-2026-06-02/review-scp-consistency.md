## B. Stale-language findings

- **[high]** UJ-4 step 1 states, as current behavior, "Sofia opens the **Audit trail list** (from nav, a tenant row, or a command result)". "From nav" is a remnant of the pre-2026-06-27 three-nav-homes IA and contradicts both the spine's own IA table ("Contextual entry — tenant row · tenant detail · user lookup · command result (not a separate Tenants left-menu entry)", EXPERIENCE.md:44) and SCP P7.4 (Audit is a contextual route). A developer following UJ-4 could add an Audit left-nav entry, violating the SCP (EXPERIENCE.md:213). *Fix:* reword to "(from a contextual entry — a tenant row, tenant detail, user lookup, or command result)". Note the PRD carries the same stale wording (prd.md:101 UJ-4 "from nav"; prd.md:307 FR-21 "from navigation") — coordinate a matching PRD errata so the spine fix does not create a new spine-vs-PRD mismatch.
- **[medium]** The freshness clause "— until then the wire vocabulary is `current` / `stale` / `unknown`" is ambiguous about the interim: per addendum §C/§D, until PLAT-FRESH-1/HOST-REF-1/UI-READ-1 verify, the current generic EventStore query route normalizes provenance to `unknown` — `current`/`stale` are the PLAT-FRESH-1 acceptance vocabulary, not claims the unverified interim transport may make. As written, a developer could read it as licensing `current`/`stale` claims over the generic route today (EXPERIENCE.md:96). *Fix:* split the two regimes explicitly, e.g. "on the unverified generic route, provenance normalizes to `unknown`; once the three packages verify, the wire vocabulary is `current`/`stale`/`unknown`, and `aging` joins it only when authoritative projection-time provenance supports it."
- **[low]** Approved-fallback #1 states "delivered for the Tenants-owned first slice by Epic 5" without an inline historical marker; the historical-evidence rider only arrives at :281/:283, so the list item read alone looks like a current completion claim (EXPERIENCE.md:277). *Fix:* append "(historical evidence, subject to reverification)" inline.

Checked and clean: "Blazor Auto" (only superseded-history framing, EXPERIENCE.md:29); client-side/client-assembled assembly (zero hits); global one-at-a-time (only superseded framing at :138/:271/:279/:281); global search (only the removal note at :41); rc.3/rc.2 (only provenance/resolved-history framing at DESIGN.md:193, EXPERIENCE.md:285); five-read language (zero hits — "five" occurs only as the 5-state freshness set, the five-item fallback documentation list, and DESIGN's "first five components"); plaintext offset paging (all offset mentions are inside the protected-cursor rule or "never offset/limit"); completion-claims-as-waivers (all blanketed by :13/:281/:283 and DESIGN.md:164).

- **[low]** DESIGN's receipt never-receives list omits "raw `NarrativePayload`" itself ("never raw event payload, event bodies, command payloads, tokens, correlation ids, ETags, raw metadata, or PII"), while PRD §10 (prd.md:355) and EXPERIENCE.md:29/:85 both name it explicitly (DESIGN.md:247). *Fix:* add "raw `NarrativePayload`" to the parenthetical list.

Semantically compatible (degraded ⊇ unavailable) but the vocabulary should match the canonical wording. *Fix:* "when Memories is unavailable or degraded".
