# Divergence review, 21 November 2026

The review found one ambiguity in hosted qualification. Cold bootstrap and authenticated REST run in the same `rest` matrix job. A release owner counting them as separate jobs could omit `anonymous-ui`, which checks access denial. Bind qualification to all four suite results from the same candidate and shipping packages. CI names them `rest`, `persisted`, `anonymous-ui` and `authenticated-ui`. [Hosted matrix and suite definitions](../../../../../.github/workflows/ci.yml#L188)

AD-14 and the build baseline distinguish the candidate's recorded Builds catalog from a developer's refreshed submodules. The host selector reads the release declaration for the catalog version. The verifier checks the restored Aspire package's producer against the executable checkout and checks the package identities in the four host manifests. This gives release and integration teams the same rule when the development checkout points to a different commit. [Host selection](../../../../../scripts/prepare-bootstrap-compatibility.sh) · [Provenance verifier](../../../../../scripts/prepare-source-catalog-profile.py)

AD-13 assigns deployment composition to the platform. Tenants owns the test fixtures that manage Aspire and daprd during an integration run. The CI profile specifies its own Dapr runtime and CLI, so a result from the Builds runtime qualification alone cannot close the Tenants release check.
