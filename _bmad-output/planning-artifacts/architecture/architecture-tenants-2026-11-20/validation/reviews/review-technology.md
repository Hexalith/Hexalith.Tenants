# Technology and implementation review

Reviewed the November 20 working-tree architecture against the Tenants source, package catalogs and focused test definitions. The technology baseline matches. Four documentation corrections would help implementers reproduce the shipped behavior. The references below are relative to the repository root.

| Severity | Architecture guidance | Evidence and impact | Suggested correction |
| --- | --- | --- | --- |
| Medium | Lines 499–500 and 660–662 associate HTTP 409 and `ConcurrencyConflict` with retrying status lookup. | `src/Hexalith.Tenants.UI/Services/Gateways/TenantCommandGateway.cs:565` handles non-success status responses. Its retryable HTTP classifier at line 718 excludes 409. Lines 949 and 1310 map the exact command-status failure reason to localized retry advice. `tests/Hexalith.Tenants.UI.Tests/Services/Gateways/TenantCommandGatewayTests.cs:2143` treats a plain submission conflict without a retryable flag as determinate for the tested correction flows. A new flow could advise polling after a definitive failed submission. | Specify recovery separately for submission, status-transport failure and a tracked command with the verified concurrency failure reason. Name the applicable command identity. |
| Medium | Lines 507–510 describe a Tenants publisher feeding the Memories index. | The four lifecycle-event registrations live in `samples/Hexalith.Tenants.Sample/Program.cs:18`. The composing host enables Memories independently at `src/Hexalith.Tenants.AppHost/Program.cs:183` and can omit the sample under the source-catalog profile at line 238. An available search endpoint can therefore receive no updates from this topology. | Identify the sample as the supplied publisher host. Require a deployed publisher with those subscriptions when claiming end-to-end indexed discovery in a composition that excludes the sample. |
| Medium | Lines 250 and 527 describe four audit states as the complete typed model. | `src/Hexalith.Tenants.UI/State/TenantAudit/TenantAuditAvailabilityState.cs:5` defines Pending, Delayed, Unavailable, Available and MissingSupport. The component handles verified availability at `src/Hexalith.Tenants.UI/Components/Tenants/Audit/AuditAvailabilityState.razor:193`. PRD FR-23 enumerates four non-success presentations. Implementing a four-value model forces a consumer to discard a real outcome. | Distinguish the four non-success presentations from the fifth, receipt-backed Available outcome. Point developers to the enum for the complete set. |
| Low | Lines 312, 533 and 604 prescribe named placeholders such as `{userName}` for resource strings. | `src/Hexalith.Tenants.UI/Resources/TenantsResources.resx:115` and the French counterpart at line 115 use the indexed composite format `{0}`. A literal name in a .NET composite format item can cause a formatting exception in parameterized copy. | Keep whole-string localization and use the same numeric argument indices in both resources. |
