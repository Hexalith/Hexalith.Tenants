## Windows/NVDA setup

Run **natively on Windows**, in a disposable checkout on a local disk, using PowerShell and a visible desktop session. A Linux/WSL headless run cannot supply Windows/NVDA speech evidence. Prerequisites:

- The .NET SDK selected by `global.json` (currently 10.0.403), Git, Node.js with npm, and access to the repository's configured NuGet feeds. Use the committed npm lockfile and root-declared dependency revisions. Initialize only missing **root-declared** submodules needed for the existing Debug source build; do not use recursive or remote updates. `Hexalith.Builds`, `Hexalith.FrontComposer`, EventStore, Commons, Memories and their source dependencies must be available in the repository's supported layout. The runner uses the existing Debug/source build with EventStore `3.128.4` and packaged McpCli; it does not upgrade dependencies. A build failure blocks the trial; resolve its prerequisite rather than skipping the build.
- An ASP.NET Core localhost development certificate (`dotnet dev-certs https --trust`). The runner accepts this local certificate for automation; trust it before manual browser work. Docker, Dapr, Aspire, an existing realm and `/proc` process data are **not required** by this standalone fixture mode. If qualifying a deployed environment instead, discover its resource state and registered endpoint through `aspire describe`; do not apply these terminal controls to it.
- Installed Chrome and NVDA for the primary pairing. Start NVDA and use Tools → Speech Viewer. Record actual settings rather than changing speech behavior to force a pass. Start Speech Viewer **before launching the runner**. Keep its transcript private until sanitized. For a second NVDA/Firefox pairing, install the fixture's Firefox browser below, record its actual build/version and the deployment support basis; if that build is not supported, the second-pairing gate remains blocked. This runner does not launch Safari; VoiceOver/Safari requires a separately supported test environment.

From the repository root in a fresh PowerShell terminal:

```powershell

```

Leave this terminal running. A headed browser opens and signs in automatically as the non-sensitive fixture operator. No realm password or source UI PID is needed. The terminal prints `Ready: en`, the disposable UI address and available controls. Keep browser zoom at 100% and the view at least 1024×800 so measured command admission is enabled. Use the opened window for keyboard/NVDA testing; commands go in the terminal. Prefer a second operator to enter them so the tester can retain browser focus. If one operator switches windows, log the focus change and wait for the required quiet interval after returning. Do not count terminal speech or browser focus reading as a live announcement.

For the second pairing, finish the first run with `quit`, set `$env:TENANTS_BROWSER_ENGINE = 'firefox'`, remove `TENANTS_BROWSER_CHANNEL` (`Remove-Item Env:TENANTS_BROWSER_CHANNEL`), and rerun with a different output filename. All matrix cells still require the declared supported build and settings.

## Terminal controls and exact actions

Controls change subsequent upstream responses; they never activate a browser button. `show` prints only modes and counters. Session ordinals/cultures/start-end times, UI activation/search-notice/availability timestamps, and sanitized response-category timestamps are written to the requested JSON path after `quit` (or terminal EOF). The packet includes source, fixture, browser, Fluent and assembly identities; the protocol still requires a separate speech transcript. Keep temporary UI/build logs private because framework logs may contain request identities. Do not enable network/body/trace recording.

| Terminal command | Effect |
| --- | --- |
| `session en` / `session fr` | Close the previous browser context, reset all controls and the retained attempt, set the production `.AspNetCore.Culture` cookie and browser locale, and authenticate a fresh circuit. Search starts up, status starts at propagation wait, projection starts held. Verify localized copy below. |
| `search down` / `search up` | Memories returns 503 / indexed candidates. Authorized tenant list/detail reads remain available. Activate the workspace Refresh to apply a change to the current surface. |
| `cursor reject-once` | While search is down, arm one rejection of the next cursor-bearing fallback list request. Cursorless reads cannot consume it. Return HTTP 400 `application/problem+json`, `reason=invalid-cursor`, then allow the UI's cursorless first-page recovery. `show` must report one `rejectedCursors`, one `recoveryPages`, and `rejectCursor=false`. No copying/editing of opaque cursors. |
| `status events` | All subsequent exact-attempt status reads return identity-matched `EventsStored`. The production gateway derives verified identity; no verification bypass exists. |
| `status unavailable` | All subsequent status reads return HTTP 200 `{}`, which the production gateway treats as unknown/unverifiable, nonpending and nonretryable. |
| `status wait` | Return status propagation-lag 404. This preserves NotStarted before first evidence and is **not C2**. |
| `projection hold` / `projection deliver` | Omit the new tenant from list and return target detail 404 / expose its exact submitted values with advanced current projection metadata. These controls do not change status. Holding means an immediate response unable to confirm, not an HTTP request left hanging. |
| `show` / `help` / `quit` | Inspect sanitized state/counters / list commands / stop and write the packet, then close fixture resources. |

S0: enter `session en` (repeat every trial with `session fr` for FR). In the browser, check the notice region starts empty, enter `needle` in the Search tenants field (`tenants-list-search`), Tab out and wait for the debounced search to finish. Create does not perform a separate audit read for these states. `CreateTenantFlow.RefreshCommandStatusCoreAsync` calls `ITenantCommandGateway.GetStatusAsync`, applies that command-status result, and then requests projection refresh/list/detail evidence. C1 first Pending follows a delivered, identity-verified EventsStored result. C2 first Unavailable must be delivered while audit is still NotStarted, before any earlier result mounted Pending. The backend may already have stored events in C2 without that proof ever reaching the UI: backend storage and UI evidence are separate observations. Record the sanitized ordering of submission, each delivered status/result category, first availability insertion, and projection responses. Keep projection confirmation held or unsatisfied for these measurements; confirmation can otherwise replace Pending with MissingSupport. If the environment cannot control the required status/projection ordering, mark C1/C2/C3 blocked. Do not substitute a later Pending → Unavailable transition or suppress status identity validation.

Use one synchronized timeline for each trial. The fixture's `handoffUiEvents` records UTC button activations, search changes, notice-set changes and first audit states (with focus); `handoff.events` records UTC response categories. Session ordinals link them across navigation. It does not capture NVDA output or timestamp individual words. Use an approved local screen/audio recorder to capture Speech Viewer and audible NVDA output with a visible UTC clock from the **same Windows machine**, after automatic sign-in has finished. Do not record authentication transitions; discard them if a session reset was recorded. Start the transcript before opening Create or searching. A second PowerShell window can supply the clock without occupying the fixture terminal:

```powershell
while ($true) {
    [Console]::Write("`r{0:yyyy-MM-ddTHH:mm:ss.fffZ}", [DateTime]::UtcNow)
    Start-Sleep -Milliseconds 100
}
```

Before the quiet interval, capture the clock and browser focus in the recording. Match the recorded Enter/click to the packet's `activation` UTC event, then transcribe actual speech with offsets against that same clock. Retain the recording/transcript together, annotate the clock's 100 ms display resolution and any recording offset, and label timing inconclusive if alignment is missing. Search changes also have a separate change event; debounce completion is represented by the first notice/state observation rather than by the keystroke. Sanitize all artifacts before sharing. Recording and clock speech must finish before the quiet interval; never interpret their sound as product speech.

For each trial, start the speech transcript before opening the surface and wait for five consecutive seconds without speech before the trigger. Record trigger time, delivered response time and the first matching DOM state time separately. From the first matching state, observe for at least 30 seconds, without navigation or another activation, and finish only after five consecutive quiet seconds. If speech or controlled responses remain outstanding at 60 seconds, retain the transcript and mark the trial inconclusive rather than truncating it into a pass. These intervals define repeatable measurement windows, not a product announcement SLA. A silent 30-second window is a measured omission, not proof that speech can never occur later. Release held responses only after the observation ends, then stop recording; preserve subsequent speech separately if relevant. Use a fresh trial for each C3 refresh selector and do not clear or interrupt the speech queue to manufacture silence.

Record whether focus moved to `tenants-create-lifecycle`, the first insertion timestamp, the separate `tenants-create-live-region` text, availability label/reason, and the synchronized speech transcript. For C3, record lifecycle and availability speech separately even when their updates share a render; the later same-state refresh must not be confused with that first insertion. Never treat command acceptance, projection confirmation or AX state alone as audit availability or spoken evidence.
