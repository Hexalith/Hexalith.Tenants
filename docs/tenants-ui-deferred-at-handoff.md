# Deferred assistive-technology handoff

Prepared 2026-10-29 for DW-116, DW-446 and DW-459. All remain open. This is a protocol for actual speech qualification; no screen reader was run during preparation. DW-446 and DW-459 describe the same first-insertion risk in different historical reviews and may share one complete evidence packet while retaining both records.

The current browser packet and exact source, FrontComposer, Fluent, validator, assembly and browser identities are in [validation evidence](../_bmad-output/implementation-artifacts/dw-116-137-446-459-466-validation-evidence.md). The tested Fluent package is 5.0.1. Rebuild and record new identities whenever source, browser, component package or AT changes; today's DOM/AX observations do not establish speech on another pairing.

Declare the primary pairing as NVDA/Chrome on Windows for the historical AT-NVDA-1.9 gate. Before execution, declare a second pairing supported by the target deployment: NVDA/Firefox on Windows or VoiceOver/Safari on macOS. Record the deployment support basis; do not leave the second pairing unspecified. Record OS, browser, NVDA/VoiceOver version, voice and language, verbosity, browse/focus mode and live-region settings. Enable NVDA Speech Viewer or VoiceOver caption/transcript capture before opening the surface. Do not retain sign-in screens, credentials, tokens, session state, internal command identities or raw network bodies.

Use an authenticated authorized operator on an approved disposable test environment. Discover the registered UI HTTPS endpoint and resource state with `aspire describe --apphost src/Hexalith.Tenants.AppHost/Hexalith.Tenants.AppHost.csproj --format Json`; keep full output private and retain only sanitized resource names/states/endpoints. Do not use production tenant data. The read-only navigation validator rejects Create commands: use a test deployment or an explicitly controlled command fixture for the manual Create cases. Preparation here sent no domain command.

The required matrix is S0–S3 and C1–C3 in both EN and FR on the declared primary pairing and again on the declared second pairing. A blocked case or missing language/pairing prevents the corresponding record from closing. Run every case using the application's configured culture mechanism, in fresh sessions with no retained command attempt. Confirm displayed copy matches the shipped resources below and record the effective culture. Use non-sensitive fixture identifiers and readable tenant names. Keep keyboard focus on the initiating control unless the flow moves it; record the actual focus target because focused text can also be spoken.

S3 is already reproduced by the existing [unattended validator](../tests/Hexalith.Tenants.UI.Tests/Browser/validate-authenticated-navigation-focus.mjs), in phase `search-composed-live-semantics`: internal `fixture.resetList` rejects the next cursor-bearing fallback read once, then permits the authorized first-page recovery while Memories remains unavailable. That internal switch is not an operator control or a manual AT test environment. Its [browser result](../_bmad-output/implementation-artifacts/dw-116-137-446-459-466-validation-evidence.md) cannot replace S3 speech. Until an existing approved test environment exposes equivalent response control, mark S3 blocked; add no control server or production hook in this work.

Create does not perform a separate audit read for these states. `CreateTenantFlow.RefreshCommandStatusCoreAsync` calls `ITenantCommandGateway.GetStatusAsync`, applies that command-status result, and then requests projection refresh/list/detail evidence. C1 first Pending follows a delivered, identity-verified EventsStored result. C2 first Unavailable must be delivered while audit is still NotStarted, before any earlier result mounted Pending. The backend may already have stored events in C2 without that proof ever reaching the UI: backend storage and UI evidence are separate observations. Record the sanitized ordering of submission, each delivered status/result category, first availability insertion, and projection responses. Keep projection confirmation held or unsatisfied for these measurements; confirmation can otherwise replace Pending with MissingSupport. If the environment cannot control the required status/projection ordering, mark C1/C2/C3 blocked. Do not substitute a later Pending → Unavailable transition or suppress status identity validation.

For each trial, start the speech transcript before opening the surface and wait for five consecutive seconds without speech before the trigger. Record trigger time, delivered response time and the first matching DOM state time separately. From the first matching state, observe for at least 30 seconds, without navigation or another activation, and finish only after five consecutive quiet seconds. If speech or controlled responses remain outstanding at 60 seconds, retain the transcript and mark the trial inconclusive rather than truncating it into a pass. These intervals define repeatable measurement windows, not a product announcement SLA. A silent 30-second window is a measured omission, not proof that speech can never occur later. Release held responses only after the observation ends, then stop recording; preserve subsequent speech separately if relevant. Use a fresh trial for each C3 refresh selector and do not clear or interrupt the speech queue to manufacture silence.

Record whether focus moved to `tenants-create-lifecycle`, the first insertion timestamp, the separate `tenants-create-live-region` text, availability label/reason, and the synchronized speech transcript. For C3, record lifecycle and availability speech separately even when their updates share a render; the later same-state refresh must not be confused with that first insertion. Never treat command acceptance, projection confirmation or AX state alone as audit availability or spoken evidence.
